# Engineering review

## Proportionality

This is a local, single-user, solo-developer project. Evaluate complexity, abstractions, safeguards, dependencies, and operational practices against their concrete utility here. Do not treat enterprise-grade completeness or generic industry practice as a requirement. Report added complexity only when it creates a demonstrated correctness, security, reliability, performance, or maintenance risk, and weigh recommendations against their technical-debt cost.

Use this for a risk-focused review of changed files. Check for logic errors, edge cases, inconsistent state, secret exposure, unsafe input or HTML handling, unclear errors, inefficient queries or rendering, missing tests, API or schema breakage, dead code, and maintainability regressions.

Group concrete findings as Critical, Major, or Minor, then give a concise readiness assessment. Prioritize real risks over style preferences.
